# Test data

All test data is fictitious and lives in `fixtures/`. It is used by the automated tests, the
in-app sample workspace, the seed script and the UI design preview.

## Libraries

| Fixture | Purpose |
|---|---|
| `libraries/example-team-library` | Main library: workflows and skills with applicability, exclusions, tool and MCP prerequisites, checks, declared evidence, an undeclared skill, a required item and team instructions. |
| `libraries/security-guild-library` | Second source: a skill whose name collides with the main library (`api-contract-review`), **invalid** metadata (`secrets-hygiene`), an undeclared skill, an executable script, and required instructions. |

## Repositories

| Fixture | What it exercises |
|---|---|
| `repos/billing-service` | Maven + Spring Boot parent, Liquibase changelogs, JPA, GitHub Actions, an existing team `CLAUDE.md`. |
| `repos/orders-api` | Gradle Kotlin DSL with a version catalog, jOOQ, an OpenAPI spec. |
| `repos/storefront-web` | React + Vite + Vitest, a lockfile pinning versions, a README that mentions Spring/Liquibase (must not count), an existing `AGENTS.md`. |
| `repos/platform-monorepo` | Mixed monorepo: React app, a Liquibase service, a jOOQ service with an external corporate parent POM (partial evidence, unresolved version). |
| `repos/inventory-gradle-multi` | Gradle multi-project with convention plugins in `buildSrc` (partial evidence → "needs information"), Flyway, an interpolated version. |
| `repos/legacy-scripts` | No supported manifests: Python and shell only; nothing should match. |
| `repos/agent-ready-service` | Already has agent files: an unmanaged `.claude/skills/jpa-entity-review`, `AGENTS.md`, `CLAUDE.md`, `.mcp.json` with another server, a Cursor rule. |

Automated expectations for these live in `crates/habi-core/tests/matching_fixtures.rs` and
`fixture_scenarios.rs`.

## Ways to use it

- **In the app:** the sample workspace on the start screen. Creates both libraries and all seven
  projects under Habi's data folder (labeled as samples). Nothing is installed yet.
- **Seeded workspace with every state:** `scripts/seed-test-data.sh [dir]` (default
  `./habi-test-data`, ignored by Git) builds the CLI, creates Git repositories for both
  libraries and the projects, installs items, publishes upstream updates, makes local edits
  (conflict, edited locally, update available), adds a declaration and a contribution draft,
  and takes the security library offline (stale). Then run the app against it:

  ```sh
  HABI_HOME=./habi-test-data/habi-home pnpm --dir apps/desktop tauri dev
  ```

  It never touches your own Habi data; delete the folder to start over.
- **In a browser:** the UI design preview renders fixtures generated by the real core, and
  the development bridge runs the UI against the real core. Both are described in
  [Architecture](architecture.md#working-on-the-ui-in-a-browser).
